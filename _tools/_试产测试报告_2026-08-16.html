三、规范 v1.0 测试发现（供 v1.1 修订参考）

  • 示例笔误§3.1 chain.json 示例自相矛盾：顶部示例 chain_id 为 history/H-M1-中央官制演进（缺 id 段），字段详解与 §8.2 为 history/H-M1-3-中央官制演进。本次按字段详解执行，建议 v1.1 统一。
  • 规则冲突§4.8 confidence 算法与 §3.2 示例矛盾：算法规定存疑 ≥4 条 → low，但示例主卡 10 条存疑标 medium。本次按算法执行（三张主卡均为 low），建议 v1.1 明确以算法为准并修正示例。
  • 数字笔误子卡字段数 13 vs 12：§3.3 定义子卡为 12 个字段（含 parent_card，无 exam/open_questions），但 §7 检查项 3 与 §11 自检 4 均写「13 个字段」。建议统一为 12。
  • 规范缺口世界史概念的 #朝代/ 标签无约定：tag 规则只给了中国朝代示例，本次世界史（启蒙运动）用 #朝代/17-18世纪。建议 v1.1 补充世界史时期标签规范（如 #朝代/近代欧洲）。
  • 规范缺口#考频/ 标签缺少数据依据：规范要求按 2023-2026 上海真题频次定级，但未提供真题统计来源。本次为 AI 估算（⭐⭐⭐/⭐⭐⭐⭐），建议 v1.1 明确：考频标签须经真题核对，或允许 #考频/待核 占位。
  • 规范缺口exam_questions 的 type 无枚举定义：§4.6 要求 5 种题型，但 JSON 中 type 是自由文本。建议 v1.1 固定枚举（单选/配对/图表排序/材料解析/开放论述）并加校验。
  • 执行口径「同时」类话语连接词的处理：§7 检查项 20 禁止「同时」，但正文中的「与此同时」是话语连接而非时间相对表述。本次按从严处理全部改写，建议 v1.1 明确词表边界（或给出白名单）。
  • 执行口径子卡字数上限偏紧：200~350 字对含「定义 + 背景 + 易错点」三段的子卡偏紧，本次多张子卡为此裁剪。若保留三段结构，建议放宽至 200~400 字，或允许易错点不计入。
  • 执行口径真题锚尚未落地：§5.2 要求练习题尽量锚定 2023-2026 真题，但 schema 无此字段且本次未查真题（不编造）。建议 v1.1 决定：加可选字段 exam_anchor，或明确「真题锚：待补」写入何处。
  • 流程建议校验脚本应入库：本次交付 _validate_cards.py（20 项 + 概念清单交叉核对 + BOM/文件名检查），建议并入规范作为官方校验器，并在每批产出后自动跑。
